# Decisions

One line per non-obvious decision: what was chosen and why.

- Keep the existing `Backend/` directory name instead of creating `backend/`; the checkout already had `Backend/` and `Frontend/`.
- Use integer primary keys everywhere; simple, portable and easy to read in URLs.
- Use SQLAlchemy async sessions with asyncpg in Docker and aiosqlite in tests; one code path, async tool calls.
- Verification state is `false_positive`, not `rejected`: `PROJECT_CONTEXT.md` §18 makes this authoritative over the task prompt, which uses `rejected`.
- Two AI functions only (`interpret`, `remediate`) as the task prompt requires; `PROJECT_CONTEXT.md` also lists a summary function — see the final report's open questions.
- Hypothesis: host scope rules match one exact host; `*.example.test` is the explicit subdomain wildcard. Default deny.
- A URL is allowed when its host has an exact in-scope host/IP/CIDR rule; when a host is scoped only through `url_prefix` rules, the path must match a prefix on a boundary (`/admin` does not match `/administrator`).
- Out-of-scope rules always win over in-scope rules, including across hosts resolved from the same DNS name.
- Ambiguous numeric hosts (decimal, hex, octal IP forms, non-canonical IPv4) are rejected, not normalised, to avoid parser-confusion bypasses.
- Docker-internal service names are allowed because they resolve into the configured private networks; the allowlist is IP-based.
- ZAP image pinned to `zaproxy/zap-stable:2.17.0` (current stable tag verified on Docker Hub on 2026-11-23).
- Reports use Jinja2 autoescape; PDF rendering is attempted at generation time and failure does not destroy the HTML report.
- All timestamps are stored in UTC with `created_at`/`updated_at` on every table; `audit_log` is append-only by contract.
- Scan jobs are in-process `asyncio` tasks (no Celery/Redis) and the API returns `202` immediately; this assumes one backend process, which the Compose stack runs.
- Nmap targets are stored as a bare host. An explicit port in a URL becomes the port filter so the profile cannot silently widen the scan; the scope guard re-checks that stored canonical target at execution time.
- The one-active-scan-per-assessment limit is a DB check in the service; the single-process assumption makes the remaining request race acceptable for this project.
- Raw evidence paths are built from generated assessment/scan IDs only, and every download resolves under `DATA_DIR`.
- Recon merges by host address: an open observation wins over closed, service detail is filled from later scans, and an unreadable scan XML is reported per scan instead of failing the endpoint.
- ZAP gets the scope guard's include/exclude regexes directly as its context, so spider and active scans cannot leave the authorized URL space even if a link points outside.
- ZAP authentication uses the `X-ZAP-API-Key` header instead of the `apikey` query parameter, keeping the key out of URLs and access logs.
- One ZAP scan at a time (global lock): ZAP's session is shared, so parallel contexts would race; the Nmap semaphore stays separate.
- The raw ZAP artifact is a bounded PenPal wrapper around the alert list, not the daemon's full session export. It keeps the fields the report and reviewer need without unbounded history.
- ZAP alert fingerprints use plugin id, HTTP method, normalized URL (query and fragment removed) and parameter name. This intentionally collapses repeated payloads of the same issue on one endpoint.
- Tool output never sets verification state, final severity or final remediation. A re-scan updates tool fields and `seen_count` but leaves assessor and AI fields untouched.
- Nmap findings are limited to notable exposed admin/database services and disclosed service versions; other open ports stay in recon rather than becoming finding noise.
- ZAP profile `active_limited` is conservative by config: one thread per host, one minute per rule, 30-minute scan cap and ten alerts per rule.
- The sanitizer redacts every IP address, not only private ones: the model does not need addresses, and redacting only private ranges would leak public targets if the allowlist were ever enabled.
- AI input carries the relative endpoint path, never the absolute host, and full HTTP messages are left to per-finding evidence capture rather than duplicated inside the tool payload.
- Redaction placeholders are typed (`[REDACTED_PASSWORD]`, `[REDACTED_COOKIE]`) so the model can still reason about context. The sanitizer is idempotent and returns per-type counts for the AI disclosure appendix.
- One OpenAI-compatible provider class covers Gemini, Groq, OpenRouter and Ollama; only environment variables change. `response_format` is retried without JSON mode once when a gateway rejects it.
- AI prompts are versioned in code (`PROMPT_VERSION`) and shared by both functions; output schemas forbid extra fields, so an attempted prompt injection outside the schema is rejected.
- AI retries transient provider failures three times with jitter, performs exactly one repair retry for invalid JSON/schema, and stores each attempt; a cache hit creates a new analysis row with zero latency instead of hiding the reuse.
- The AI cache key is provider + model + prompt version + exact sanitized prompt, so identical evidence can reuse a result across findings but never across providers or prompt versions.
- Bulk analysis runs in a background in-process task, serially per job, one job per assessment; progress is in memory and results are in `ai_analyses`, consistent with the single-process deployment.
- AI may set only `ai_suggested_severity`. Final severity, verification status and final remediation remain assessor-only fields, and tests assert they survive re-analysis.
- "Effective severity" is final severity for confirmed findings, otherwise AI-suggested when present, otherwise tool severity. Finding filters, sorting and dashboard counts all use this one definition and the dashboard labels it.
- A false-positive decision clears final severity and final remediation; a needs-retest decision clears final severity unless the assessor supplies one. Confirmed is the only decision that contributes to report severity.
- Confirming without a final severity falls back to AI-suggested then tool severity and writes `severity_defaulted=true` into the audit row, so the shortcut is visible later.
- Manual findings use a fingerprint of title + endpoint + parameter and are refused as duplicates within one assessment; tool findings keep their provider fingerprint.
- Evidence uploads require matching extension, MIME type and magic bytes (PNG, JPEG, PDF; UTF-8 text), are capped by `MAX_UPLOAD_BYTES`, and are stored under a UUID filename. Notes are text-only and size-limited.
- Evidence listing exposes note/exchange content and the stored filename but no file-download endpoint, because the API contract does not define one; report generation reads the stored file directly.
- Dashboard numbers come from aggregate queries (grouped severity/status/category, distinct AI coverage, one scan query), so the endpoint stays one request without per-finding follow-ups.
- Reports include confirmed findings only; false-positive and needs-retest counts go to Appendix A and pending findings are omitted entirely.
- Evidence is truncated per item in the report but never truncated in the database; the report keeps the evidence SHA-256 so the full record remains traceable.
- Jinja autoescape is set explicitly instead of via `select_autoescape`, because the template ends in `.j2` and extension-based selection would turn autoescaping off.
- If WeasyPrint fails, the report row becomes a ready HTML report with `pdf_fallback=true` and a safe error message. This keeps the HTML deliverable usable instead of losing it behind a failed PDF request.
- The PDF renderer is a module function invoked through dependency injection in tests, so no test needs system Pango/GTK; the container remains the only place a real PDF is produced and verified.
- Report files live in `DATA_DIR/reports/{assessment_id}/report-{id}.{ext}` with a SHA-256, and downloads resolve inside `DATA_DIR` like raw scan output.
